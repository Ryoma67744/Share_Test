# 解析処理の応答性（2026-11-10）

共有プロジェクトの原本待ちを解消した `de26e62` と、数値処理をWorkerへ移した実装を、同じChromium・同じ合成原本で比較した記録です。本番データやSupabaseの設定は変更していません。

## 測定

同じ原本内の2列から比画像を作成します。欠測、ゼロ、負値、重複座標を含め、背景TIC生成も通常どおり動かしました。静的アセットの読み込み時間は測定対象外です。解析開始から完了までの時間と、16msタイマーの最大実行間隔を測りました。後者は画面のイベント処理が止まる時間の目安です。

| 測定行数 | 修正前の総時間 | 修正後の総時間 | 修正前の最大間隔 | 修正後の最大間隔 |
| --- | ---: | ---: | ---: | ---: |
| 100,000 | 796ms | 843ms | 541ms | 17ms |
| 500,000 | 3,674ms | 4,182ms | 2,621ms | 38ms |
| 1,000,000 | 9,093ms | 11,294ms | 6,254ms | 43ms |

今回の合成データでは総計算時間が約6〜24%増えました。改善したのは解析中の操作応答であり、すべての解析が短時間で完了することを示す測定ではありません。再利用時の同じ比の取得は1〜2msでした。実測値は端末・データ形式・他の処理によって変わります。

全サイズで、値・有効判定・無効理由・分母対応・元行ID・ラスタのSHA-256、統計、座標情報、Range上限が修正前と一致しました。原本のバイト列、入力参照、保存された比の定義も維持されています。

## 実装と検証

画面表示と解析は1つの数値Workerを共有します。元のパーサー、幾何、統計、Rangeの関数をそのまま実行し、比の計算・MRM照合の規則は変更していません。ユーザー操作から続く処理を背景TICより優先し、キャンセルした利用者だけを待ち合わせから外します。古いWorker結果は現在の画面へ適用しません。

Worker内では計算中だけ通常の配列を使い、保持・転送にはFloat64の配列と元セルの情報を使います。TXTの字句、XLSXの式・型・エラー、RAWの座標、Parquetの精度判定も維持します。特にParquetの型付き配列に付いたセル情報は、Worker間で消失しないよう別フィールドで渡します。

`node tools/test.cjs` が数値一致、キャンセル、待ち行列、キャッシュ破棄、原本の保持を検証します。`node tests/msi_ratio_analysis_browser_regression.cjs` は実際の画面とWorkerで10万行を計算し、修正前の固定結果と比較します。機械ごとに変わる時間を固定値で合否判定せず、解析中に画面のイベント処理が動くことを確認します。

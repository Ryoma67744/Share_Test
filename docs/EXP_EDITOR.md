# 既存 .exp のMRM編集

MRM管理の「.exp を開いて編集」から、過去のメソッドを独立した表で編集できます。
原本の設定を保持した別名の `.exp` を保存し、必要な行だけを別操作でMRMライブラリへ登録します。

## 対応範囲

この版は、現在のアプリの固定テンプレート出力が用いる**単一のフラットなMRMブロック**を、キー構造で検査して読み込みます。
すべてのWaters機種・MassLynxバージョンに対応する形式変換器ではありません。
実際に過去使用した `.exp` は今回の開発時点で未提供のため、実機互換性は未確認です。

- 編集項目: 化合物名、Precursor、Product、CV、CE。
- 同じMRMが複数行あっても、行数・順序を保持します。
- Precursor/ProductはMRM側とSIR側の対応する記載を一緒に更新します。
- Dwell、Delay、AutoDwell、測定時間、極性、化学式、コメント、その他の行は原本のまま保持します。
- 無編集、または値を元に戻した場合は、元ファイルと同じバイト列を返します。
- `.exp` 原本の上限は1 MiBです。チャンネル件数の読み込み上限は処理資源を保護するためのもので、装置の取得可能件数を保証しません。
- UTF-8、UTF-16 LE/BE、明示指定したWindows-1252とShift_JISを扱います。自動判定はBOMまたは厳密なUTF-8読取に限定します。
- 必須キー欠落、重複番号、MRM/SIRの質量不一致、複数Functionなどは、説明を表示して拒否します。
- サンプルリストから質量を参照する設定やLockMassに依存する構造は、この版の編集対象外です。

**行の追加・削除・並べ替えは未対応です。** チャンネルごとの関連項目、件数、測定時間の更新を実際の形式・装置仕様で確認してから拡張します。
既存ライブラリのMRMを利用する場合は、1行を選び「選択した1行をライブラリのMRMで置換」で5項目をコピーできます。
原本とコピー元の極性が一致していることを確認できる場合だけ利用できます。

## 操作

1. MRM管理を管理者として開き、「.exp を開いて編集」を押します。
2. `.exp` を選びます。文字コードが判定できなければ明示指定して再選択します。
3. ファイル情報、警告、チャンネル数、各行の「条件を表示」を確認します。
4. 表の値を編集します。変更されたセルと入力エラーが表示されます。
5. 「編集した .exp を保存」で別名ファイルをダウンロードします。
6. 対象のMassLynxで開き、変更した項目と保持されるべき測定条件を確認します。

元ファイルや共有の出力テンプレートを自動で上書きすることはありません。
編集だけでは、ライブラリ・使用履歴・既存のメソッドセットは変更されません。
従来の「選択を.exp出力」は引き続き共通テンプレートによる生成です。

## 作業内容とメソッドの保存

- **作業ファイルを保存**: 原本バイト列、文字コード、編集値、原本のSHA-256を含むJSONをダウンロードします。「作業ファイルを開く」で復元できます。JSON自体をMassLynxへ渡すことはできません。
- **メソッドとして保存**: 原本と編集値をDBに保存します。保存したメソッドを開くと、元の条件を保持したまま編集を再開できます。
- 既存メソッドの更新には版番号を使います。他の画面が先に更新した場合は、上書きせずエラーになります。必要なら別メソッドとして新規保存してください。
- 同名の新規保存で別メソッドを無条件に置換しません。
- ファイル読取・編集・ダウンロードはブラウザー内で処理します。DBへの送信はライブラリ登録／メソッド保存を選んだ場合に行います。

## ライブラリへの登録

登録する行をチェックし、「選択したMRMをライブラリへ登録」を押します。
極性、タグ、新規化合物の登録先、既存MRMとの照合結果を確認して実行します。

| 結果 | 動作 |
| --- | --- |
| 同一化合物・極性・Precursor/Product/CE/CV | 既存トランジションを再利用 |
| 同じ化合物で条件が異なる | 画面で条件追加を確認してから、新規トランジションとして追加 |
| 新規化合物 | 指定した登録先に、確認レベル「未確認」で作成 |
| 同名で極性が異なる／既存極性が不明 | 自動統合せずエラー |
| 必須数値が欠損 | 登録前に補正または対象から除外 |

既存の棚、確認レベル、極性、備考、Role、推奨、強度メモは保持します。指定したタグだけを追加統合します。
棚・確認レベルは化合物単位です。検証済み化合物へ新しい条件を追加すると、その分類を共有する点を確認してください。
作成しただけのファイルは実測の証拠になりません。取り込みだけで測定履歴は作成しません。
登録は全件成功または全件ロールバックです。通信結果が不明な場合は一覧を確認し、再実行できます。同一の完全な条件は再利用されます。
他の画面で登録先の内容が変更されていた場合は、照合結果を作り直して確認します。

## DB更新

既存のセットアップを済ませた後、次の順で適用します。

1. `supabase/mrm_library.sql`
2. `supabase/mrm_reconcile.sql`
3. `supabase/mrm_exp_import.sql`

最後のSQLで、専用の一括登録RPC、原本付きメソッド保存用テーブル／RPC、採番の競合対策を追加します。
再適用できる設計です。既存SQLを後から再適用した場合も、最後に `mrm_exp_import.sql` を再適用してください。
本番DBへの適用は自動では行いません。

DB更新前でもファイル編集・ローカル保存は利用できます。登録・メソッド保存のRPCがない場合は、必要なSQL名を画面に表示します。
DBのアクセス制御は既存MRM管理と同様に管理者パスワードによるRPCに限定します。

## 開発・検証

解析と差分出力は `mrm/exp-core.mjs`、画面は `mrm/exp-editor.mjs`、登録候補の照合は `mrm/exp-library-import.mjs` に分けています。
原本の解析・編集結果の復元は同じcoreを使います。復元JSONを信頼してそのまま出力しません。

`tests/fixtures/exp/` のサンプルは明示的な合成フィクスチャです。装置由来の正式仕様を証明するものではありません。
テストでは、原本のバイト一致、1項目だけの変更、SIR/MRMの整合、文字コード、未知の行、入力拒否、登録の原子性・重複防止、保存版の競合を確認します。

実際に取得したメソッドと対象機種・MassLynx/SCNを用いた読み込み・保存確認は、運用前の受入検証として残ります。
複数Function、行構造変更、異なる機種への対応は、その実ファイルを確認して拡張します。
